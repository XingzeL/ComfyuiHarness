# LoRA 管理准则

沿用 ComfyUIAPI 的简单形式：每个 LoRA 一个资料文件夹，README 是主要档案，另存本地例图与 previews.json。不额外建立重复的多层元数据系统。

## 目录与分类

资料统一位于 `loraInfo/<功能>/<基底>/<LoRA名称>/`。

- `character`：角色。
- `stylize`：画风。
- `action`：动作。
- `scene`：场景。
- `effect`：效果、服装、材质等。
- `turbo`：加速。
- `other`：暂无法归入以上功能。

每个功能内部再按 LoRA 的基底模型分类。基底名称必须保留必要的兼容性区分，例如 `anima`、`anima_29b`、`illustrious`；仅在实际需要时创建这些目录，不预设目标电脑一定使用这些模型。

每个功能下预留 `unknown/`，容纳尚未核实基底的档案。基底未知时不能自动选用；核实后移入对应目录。

一个 LoRA 按主要功能归档，其他用途在 README 中说明，不为多个用途重复建档。不同基底版本分别归档；同一基底的多个版本通常在同一 README 中列明，使用要求差异较大时再拆目录。

## 权重存放

权重放在本机配置指定、ComfyUI 实际可识别的 LoRA 根目录中，资料目录不存权重。初始化时发现搜索目录并确认默认下载目录，不写死原电脑盘符或整合包路径。

新下载权重可采用与资料一致的功能、基底分类；已有权重原地登记，不为整理资料而自动移动或重命名。README 记录实际加载名称及相对路径，不能从资料目录推断权重位置。

## 档案内容

从 [LoRA 档案模板](../resources/lora.template.md) 创建 `README.md`，包含：

1. 名称、主要功能、用途、来源链接，以及来源提供的模型/版本/文件 ID。
2. 基底及具体版本要求、权重相对路径、文件大小和 SHA256。
3. 触发词、作者推荐的 model/CLIP 强度、CFG、步数、采样器及特殊加载要求。
4. 简单使用说明或可选配置示例，注明验证情况；不要求为同一角色保存不同工作流配置，由本次 Agent 适配实际节点和字段。
5. 例图、使用限制和必要实测备注。

基底是必填项；无法核实则明确标为未知。优先依据来源版本信息与作者说明，不只凭文件名推断。同一 LoRA 的不同基底不能混用参数和例图。

作者未提供的参数写“未提供”，本机经验另列。明确区分“无需触发词”和“触发词未知”。仅计算本地 SHA256 时，不能声称已与来源哈希比对。

例图使用 `preview_01.jpg` 等编号名称，`previews.json` 仅记录来源 URL、本地文件名和必要说明。实际扩展名以图片格式为准。无例图时可先登记并注明缺失，不伪造图片。

## 角色 LoRA 的默认选用

Agent 每次生成或重绘前都查看 `loraInfo/character/<当前基底>/` 的角色 LoRA，并结合任务中的目标角色选择。目标角色有当前基底兼容、文件可加载的 LoRA 时默认加载；录入本目录的角色 LoRA 应优先用于对应角色任务。用户本次明确要求不用时按用户要求执行。

不是把当前基底下所有角色都同时加载。目标角色有多个兼容版本时选择合适的一份，避免无依据地叠加同一角色的不同版本。基底未知或文件缺失要如实处理，不能以近似文件顶替。

同一角色不维护多套工作流配方；README 记录角色、基底、文件、触发词和推荐参数即可。由本次 Agent 根据实际工作流决定加载字段、节点、强度和提示词位置。

换角色时先由 LLM 直接查看图片，分析人物、发色瞳色、服装、姿势、构图及对应 tag，再结合 WD14 反推和用户要求决定：删除哪些原特征、保留哪些内容、补充哪些目标角色特征。WD14 是辅助信息，不能替代看图；没有 WD14 结果时不得伪称已识别。不要机械替换所有标签或将完整角色描述重复注入多个过滤节点。

## HTML 浏览目录

统一入口为 `loraInfo/index.html`，已建立明确标识的占位页。当前只规定入口、资料来源和功能/基底分类；具体生成及维护方式由目标电脑的 Agent 与用户确定。

页面按功能分区、按基底分组，提供名称搜索、功能和基底筛选。卡片展示例图、名称、基底、触发词、推荐强度、来源及档案入口。无例图或参数未知时明确显示。

新增、更新、删除档案或例图后都要刷新 HTML，确认新条目可见、分组正确、原有条目未丢失、链接与例图有效。磁盘可加载清单与资料 HTML 是不同产物，不能只更新其中一个就报告维护完成。

沿用原项目名称预留 `loraInfo/_gen_catalog.py`（磁盘清单）和 `loraInfo/_gen_catalog_html.py`（HTML 刷新）。两者目前只返回待实现，清单输出 `LORA目录.md` 和 HTML 均为占位。具体实现和录入由目标电脑 Agent 按用户需求完成，不将占位入口或页面当成已经维护的目录。下载入库 Skill 尚未加入。

## 规则与容器同步

确定新的整理规则时，同时更新规则文件并创建对应容器目录。只创建已经确定的层级；具体基底和 LoRA 目录在录入时按需建立。

空目录不能代表模型已安装或能力已实现。本包的功能目录及 unknown 容器已预建；仅保留文件的传输方式（例如 Git）可能忽略空目录，初始化 Agent 应按本节重建缺失的容器。
