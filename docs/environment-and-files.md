# 环境与文件规则

## 环境发现

先确认服务地址、当前队列、ComfyUI 版本及运行环境。优先复用用户提供的地址和已有配置；本机查找只用于定位已安装服务，不扫描未知主机。

`config/environment.local.json` 保存本机配置，示例文件只含可公开的占位信息。启动命令、Python 路径和模型目录属于机器层；不要写进通用规则或每个工作流。

用 `/system_stats` 检查可达性，用 `/object_info` 读取实际节点字段和可选模型。模板只检查其能验证的事实：服务可达、类型存在、参数可接受。不据此宣称显存足够、LoRA 真正兼容或生成质量合格。

模型可能通过额外模型路径注册。保存 ComfyUI 实际接受的相对名称；不要假设所有电脑都使用某整合包或固定 models 子目录。没有本机文件访问能力时，资源盘上路径标记未知，仍可查询节点枚举。

## 图像像素上限

本机 `config/environment.local.json` 使用 `limits.max_image_pixels`，单位为像素数（宽 × 高）。示例值为 null，表示尚未确定，不表示不限制。

正式投递前必须取得已确认的正整数上限。缺失、null 或无效值时提醒用户确认并配置，本次不投递；不能自行沿用原电脑的 1,640,000 或 3,600,000。用户确认后的值再写入本机配置。

超过上限时暂停投递，报告尺寸、像素数和上限，由 Agent 降低尺寸或经用户确认调整配置。任务中的宽高或 scale_by 不能绕过此上限；工作流可使用更严格的限制，不自行放宽本机上限。

当前逐模块模板检查主采样画布，公共参考运行器检查其画布和上传输入图，并将检查结果写入任务记录。离线 build/dry-run 可以不配置，但不能把离线通过当作预算检查通过。

缩放计算交给目标电脑的 Agent，根据实际输入图、工作流、模型和硬件处理，HarnessUI 不再提供统一缩放计算模板。Agent 将计算结果写入本模块对应节点，并在投递前检查相关阶段尺寸，尤其是放大和二段采样后的实际尺寸。

现有 image_limits.py 仅负责配置上限检查，不负责自动缩放。检查不能视为显存足够的保证；batch、模型大小、精度和其他节点仍影响显存。

## 目录职责

- `config/`：机器配置；不保存密钥到发布包。
- `scripts/`：按功能命名的本机服务入口，状态及补齐方法见 [脚本说明](../scripts/README.md)。
- `test/`：Agent 按本次任务生成的测试脚本；不用旧脚本限定测试方式。
- `resources/`：登记与档案，不放权重。
- `modelInfo/<类型>/`：按本机 ComfyUI models 一级目录预留的空资料容器，覆盖模型、编码器、检测器等资源，不表示已安装；LoRA 档案仍归 loraInfo。
- `workflows/<id>/`：工作流模块的 API、CLI、配置、构建逻辑、API 图和说明；任务脚本放其 runs 子目录，成图放其 output/YYYYMMDD，任务记录放其 output/jobs。
- `Grokbot/input/`、`Grokbot/output/`：沿用原项目入图与输出汇总规则，见 [输出与汇报](reporting.md)。`inputs/` 仅保留给公共参考样例。
- 包根 `runs/<run_id>/` 和 `outputs/<workflow_id>/<日期>/<run_id>/`：仅用于已有公共运行器参考样例。逐模块工作流以自己的 output 和 output/jobs 为准；文件名使用技术信息，不带内容描述。
- `tmp/`：可重建的一次性中间文件和测试隔离目录。
- `buffer/<主题>/`：归属、路径或处理方式未确定的内容与待提炼经验，不作为可随意清理的 tmp；维护方式见 [缓冲与迭代规则](maintenance.md)。
- `archive/buffer/`：已处理缓冲主题的归档，保留结论及正式文件去向。

路径相对包根解析，与终端的当前目录无关。工作流模板相对自身目录解析。资源名称相对 ComfyUI 的对应资源搜索空间解析，绝非相对 HarnessUI。

图像输入先放入 Grokbot/input，同名加后缀，再按原项目方式传绝对路径给模块。公共参考运行器仅接受包内相对路径，也可引用 Grokbot/input 中的文件。模型权重不复制进包。

## 保留与清理

每次提交新建唯一 run，重试也新建。输出下载使用排他创建，已有文件只在来源和内容摘要与记录一致时复用。

默认保留逐模块的 output/jobs 和成图，以及公共参考样例的 runs/outputs。它们共同组成复现依据；PNG 中是否带工作流元数据不能替代这些记录。

仅清理本次产生且已无消费者的 `tmp/` 内容。清理前确认解析后的路径仍在该目录，不能跟随符号链接清理包外目录。首版没有自动删除命令，避免把旧项目的广泛任务清理行为带入。

迁移启动包无需复制个人 `*.local.json`、输入、运行记录和输出。需要迁移进行中的任务时，连同对应 run 和已收集输出复制，并保留原服务定位信息。

buffer 中尚未处理且有继承价值的主题随维护交接携带；archive/buffer 按需携带，正式规则及变更记录保留。不要把不确定内容无记录地散放在模块根或误删为临时缓存。
