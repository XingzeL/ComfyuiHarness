# 输入输出汇总与汇报

沿用原项目 Grokbot/input 和 Grokbot/output 的职责，目录位于当前 HarnessUI 包根，不保留原电脑绝对路径。

结果检查和汇总分别预留 scripts/check_outputs.py、scripts/collect_outputs.py；目前是待实现占位，具体处理由本机 Agent 按工作流完成。

## 输入与成图

- 要处理的图片先放入 `Grokbot/input/`，再将实际绝对路径传给对应模块；同名加后缀，不覆盖已有输入。
- 模块按自己的保存节点写入 `<模块>/output/YYYYMMDD/`；使用 ComfyUI 默认输出目录的工作流遵守其 README 的定位方式。
- 在确认本轮任务已完成、检查图片后，将每张有效成图复制到 `Grokbot/output/`，每个任务至少保留一份有效结果。复制时不覆盖；重复检查已归档结果时避免反复产生副本。
- 原模块结果保留。归档文件使用唯一技术前缀，不带原图标题、场景、服装、动作等内容描述。

## 提交轮汇报

通过预检后异步入队，返回后结束投递操作。说明模块、目标角色、LoRA 及强度、种子、缩放/尺寸、服务与最近输出检查结果，以及 prompt_id、manifest 和预期输出位置。

此时只汇报已入队，不能说成图已完成。普通投递轮不轮询或复制本次输出；用户要求等待、检查结果，或后续轮次中再处理结果。

## 结果轮汇报

报告实际完成/失败数、黑图与恢复情况、最终模块路径和 Grokbot/output 汇总路径。黑图最多三次恢复重启的规则见 [任务规则](tasks.md)。

默认只汇报路径和参数，用户要求时再在聊天中展示图片。用户要求插队时使用工作流已有的队首提交能力。
