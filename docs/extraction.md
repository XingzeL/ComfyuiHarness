# 提炼来源与设计取舍

工作流管理已按用户确认回归当前 ComfyUIAPI 的逐模块封装、异步投递与原保存节点方式，见 [工作流管理规则](workflows.md)。下文关于集中运行器的描述仅适用于初版保留的公共参考样例。

以下路径描述原 ComfyUIAPI 项目的来源，只作为追溯信息。启动包运行不读取这些文件，复制时不需要携带它们。

## 保留的核心

- 原 `RULE.md` 的任务分析、输入输出隔离、避免覆盖、预检与结果检查：提炼为环境、资源、任务三份规则；机器专有字段移入 local 配置。
- 原 `loraInfo/LORA加载说明.md`、资源分册、`checkpointInfo/registry.py`：保留登记 ID、相对名称、基底兼容性、加载位置、触发词、model/CLIP 强度和组合顺序。
- 原各模块 `models.py / workflow_builder.py / api.py / comfy_client.py`：保留参数解析、修改图副本、HTTP 提交和追踪思路；新模板集中公共行为，以描述文件承载节点映射。
- 原批次 Skill、`interrogate/runs/batch_engine.py`：保留筛选→规划→检查→提交→验证的方法，以及分组策略和历史图源去重的概念。没有移植其特定任务依赖和硬编码 WD14 路径。
- 原 `RULE.md` 对比测试部分及编辑器规则：保留最终分辨率、采样和变量控制的原则，置于工作流方法参考中。

## 主动改变的地方

- 原任务清理规则及 `post_submit_cleanup.py` 可能删除 task、prompt、manifest；而批次去重和恢复又依赖历史记录。新包永久保留运行依据，临时文件单独放 tmp；不复制原清理器。
- 新增工作流沿用原项目逐模块封装；提供可复制的模块模板，不强制走初版公共运行器，也不自动加载插件。
- 保留工作流原保存方式，包括 Image Save 直接写本模块目录及标准 SaveImage 写 ComfyUI 输出目录；具体位置与核验方式在模块中明确。初版公共样例的 /view 收集继续可用。
- 原提交接口并非全部内置预检；新模板 submit 在 POST 前统一检查实际节点定义和资源枚举，仍不把它描述成完整 GPU 健康检查。
- 原配置登记对整合包层级有假设；新包通过服务发现模型名称，本机根和额外搜索路径作为环境记录。
- 原通用批次引擎默认等待组，但规则又偏向异步；新包提交只入队，状态查询和收集分开，不提供隐式轮询。
- 原旧模块别名存在含义重叠（例如预留的入图精修与 2.9B hires）；新包不继承旧别名，只按明确工作流 ID 路由。

## 降为工作流经验

每张 text2imgAnima 前重启、检测数量阈值、提示词角色权重上限、缩放像素预算、指定质量词、零宽字符 seed 注入和固定 LoRA 白名单，均依赖原环境或模型，不进入通用模板。

这些内容未来可以在相应工作流档案中记录依据、适用版本和停止条件。没有证据时不把一次故障解释为普遍规律。

## 不复制的内容

具体角色/风格档案全集、模型权重、历史图片、批次任务、临时脚本、缓存、下载凭据、原电脑绝对路径。不复制绑定原机器的进程管理实现；scripts 中已放置四个功能占位入口，由目标电脑 Agent 按实际配置补齐服务管理逻辑。

## 验证依据与边界

实现时只读核对了本机 ComfyUI 的 server.py 与 nodes.py：节点定义、prompt/queue/history/view/upload 接口和标准 SaveImage 结构。运行测试使用独立模拟服务，未请求当前 ComfyUI，也未验证其 GPU 执行。

新包由规则与方法主导，基础 SDXL 图只是演示映射和调用的可替换样本，不代表推荐模型或所有机器通用的生成质量方案。
