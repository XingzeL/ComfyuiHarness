# 目标电脑验收步骤

1. 在独立目录打开整个 HarnessUI，确认不需要访问原项目。
2. 按实际环境填写 local 配置；检查服务地址、节点类型、模型名及资源 family，不接受占位值。
3. 用模块 run.py --dry-run（公共参考样例可用 build）确认 prompt、资源名称、种子、保存节点及目标路径正确。
4. 检查服务端节点、输入字段、连接及模型枚举；使用模块预检或只读 API，公共样例也可用 inspect。无法检查的自定义部分记录为未知。
5. 在已有授权范围内投递一张中性内容图片；未授权真实生成时停在准备完成，说明剩余验收步骤。
6. 返回 run_id/prompt_id 后异步结束提交；后续查询直至确定执行结果，不用“队列为空”判断成功。
7. 后续轮次按模块保存方式检查实际文件，验证可读、尺寸、路径及参数记录；仅需收集的模块才执行收集，不要求直接落盘模块先 collect。异常结果保留供诊断。
8. 后续检查或归档不应覆盖已有结果；重复生成另建 run 和唯一文件名前缀，记录与原任务的关系。
9. 把环境、依赖、资源版本、真实 run_id 和验证范围写入工作流档案；未测系统不标记支持。

第一次验收优先少量图片与适中分辨率，具体参数按已选模型和硬件确定。这里不规定跨模型通用的步数、CFG 或 LoRA 强度。
