# 搭建与接入方法

## 从图推导接口

从最终保存节点回溯，而不是先找某个熟悉编号。区分实际参与输出的图、孤立实验节点和预览节点。记录每个阶段的输入输出数据类型、尺寸变化、随机源及模型变换。

先得到一份目标环境可运行的最小 API 图，再提取频繁变化的参数。每个字段属于以下一层：机器配置、资源档案、工作流固定结构、单次任务参数。不要为每个节点输入都添加用户选项。

关键映射应验证 class_type 和 inputs 字段，避免节点重编号后静默改错节点。API 图中的连接使用 `["节点ID", 输出索引]`，不能当普通数组参数重写。

## 基础工作流

传统 SDXL 一体化 checkpoint 的示例链：

```text
CheckpointLoaderSimple ─MODEL───────────────────────────┐
                       ├CLIP─ CLIPTextEncode 正/负 ──────┤
EmptyLatentImage ────────────────────────────────────────┤
                                                       KSampler
                       └VAE─────────────────────────────┤
                                                       VAEDecode → SaveImage
```

LoRA 插在模型加载与采样/文本编码之间。标准 LoraLoader 的 MODEL 接采样器、CLIP 接两个文本编码器；VAE 不经过 LoRA。

分拆 UNet/文本编码器/VAE、特殊 conditioning、模型补丁或非标准采样器需要按模型体系重新建图。不要把上图当成任何模型通用方案。以目标已安装节点定义和可信工作流为依据；不猜不存在的类名。

## 依赖记录

记录每个非基础节点的包名、来源、已验证版本或提交号；区分 Python 包、自定义节点和模型文件。节点存在只说明类已注册，不能证明模型补丁、CUDA 和 attention 后端已正确工作。

模板的 inspect 不安装依赖，也无法证明权重语义兼容。依赖无法核实时标记未验证，先把能检查的部分完成。

## 扩展方法

- 图生图：确认 LoadImage 返回值、上传名、缩放及 VAE 编码，再调整采样降噪。
- WD14：打标只是候选筛选，人数和特征可能误识别。阈值、模型和依赖归属于该能力，不进入公共客户端。
- 批次：每个任务有独立 run/seed/manifest；明确串行、分组或异步策略。资源紧张时调整并发，不默认清空队列。
- 多阶段精修：分别记录首段、放大、精修与 Detailer 参数；latent 尺寸不等于最终图片尺寸。
- 特殊输出节点：研究实际保存规则与历史结构，编写独立收集适配；不能仅凭预测文件名确认任务成功。
- 模型实验：写清控制变量、种子、步数和最终分辨率。参数未对齐时明确比较范围，不冒充单变量实验。

不继承原项目的零宽字符 seed 注入、固定重启、固定标签权重和固定检测阈值，除非当前环境的可复现实验支持它们。
