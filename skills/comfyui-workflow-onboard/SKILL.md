# 接入 ComfyUI 工作流

目标：留下目标机器可理解、可调用、可验证的工作流，而不是复制原电脑的节点编号、路径或经验参数。

本技能随 HarnessUI 整包使用。先定位包含 `AGENTS.md`、`harnessui/`、`workflows/` 的包根；不存在时请补齐启动包，不能依赖原项目路径。Agent 是否自动发现本目录由宿主决定，可按 AGENTS 中的链接显式读取。

## 1. 发现环境与任务边界

确认目标能力、输入形式、最终输出，以及服务地址。复用已有本机配置；未知且无法发现的关键选择才向用户询问。

通过 `/system_stats`、`/object_info` 及可用的本机安装信息确认节点、模型可选名称和运行环境。模型搜索可能包含额外目录。信息不足标为未知，不推断已经安装。

先阅读 [环境规则](../../docs/environment-and-files.md) 与 [资源规则](../../docs/resources.md)。安装、下载、重启和真实生成不是“读取技能”自动获得的授权；遵循用户已授权范围，不重复确认已明确授权的操作。

## 2. 选择接入路径

- 已有 API JSON：识别最终输出，沿上游追踪输入、编码、模型、LoRA、采样和保存节点。
- 只有 UI JSON：在目标 ComfyUI 导出 API 格式，或用已验证且支持其节点的转换器。不能把 UI widgets 的顺序当作可靠输入字段。
- 没有工作流：参照 [搭建方法](references/onboarding.md)，用目标机器存在的标准节点组成最小链；先确保模型、文本编码器和 VAE 配套，再添加精修等阶段。

## 3. 建立工作流边界与映射

为新能力创建独立工作流目录，保留来源图。将语义参数映射到节点编号、预期 class_type、输入字段；多个采样阶段分开定义参数，不无条件同步所有 seed/denoise。

遵守 [工作流管理规则](../../docs/workflows.md)：沿用 ComfyUIAPI 的逐模块封装，复制 `../../templates/workflow_module/`，在模块自己的 models / workflow_builder / api 中实现参数转换。保留原保存节点及异步写盘方式，不强制所有工作流使用公共运行器，不新增自动加载适配器。原有公共参考样例的 spec 映射是可选示例。

资源使用登记 ID。明确 LoRA 的加载顺序、model/CLIP 强度与实际字段。把 prompt 文体、质量词、权重经验放在工作流说明，不提升成全局规则。

每次生成或重绘先查看 loraInfo/character 当前基底的角色 LoRA，目标角色有兼容且可加载的 LoRA 时默认使用。本次 Agent 负责实际工作流接法，不为角色保存多套工作流配置。换角先由 LLM 看图分析 tag，再结合 WD14 与用户要求决定过滤和补充。具体规则见 [LoRA 管理准则](../../docs/lora-management.md)。

参考 [接口定义](../../docs/interfaces.md) 与基础模板 `../../workflows/basic-t2i/`。标准 LoRA 示例在 `../../workflows/basic-t2i-lora/`。图像输入可用 `image: true` 参数；特殊保存节点需明确实际输出收集方式。

## 4. 分层验证

先补齐并阅读模块 README 的「运行规则」，确认特殊要求由哪个本模块 API/脚本执行。本机重启命令从环境配置或服务脚本取得；必须区分投递前与执行完成后，异步返回不能触发完成后操作。必需能力未配置时明确停止，不绕过要求。

确认本机 limits.max_image_pixels 已设置；未确定则提醒用户并暂停正式生成。检查输入、采样及放大等相关阶段尺寸，不能用原电脑的像素常量或仅凭 GPU 型号代替用户确认的预算。离线 dry-run 可以先做，但不代表预算已通过。

缩放计算由本次 Agent 根据实际图片、模型、硬件和工作流完成，直接写入本模块节点或代码；不要求额外建立通用缩放模板。保留对各相关阶段尺寸的上限检查。

脚本入口固定为包根 scripts/start_comfyui.py、stop_comfyui.py、restart_comfyui.py 和 status_comfyui.py，由本机 Agent 补齐占位实现。确认黑图后按 [任务规则](../../docs/tasks.md) 最多三次恢复重启，仍黑则告知用户。测试脚本按本次任务现生成到 test/，不要求旧测试模板。

先用模块 run.py 的 dry-run（公共样例可用 build）检查参数、连接、保存节点和种子，再核对在线节点和模型枚举。缺失依赖形成清单，不擅自替换。

在用户授权的生成范围内执行最小冒烟任务；如当前只授权接入准备，则将真实生成保留为待验证项。异步提交后结束投递轮，后续按模块输出说明检查实际文件；status/collect 仅是公共样例的方式，不是直接落盘模块的必经步骤。

不把工作流成功导出、离线检查通过、服务在线或得到 prompt_id 视为生成验证通过。

## 5. 交付

按照 [工作流档案模板](references/workflow.template.md) 说明用途、依赖、输入输出、参数、资源和验证范围。保留可运行任务示例和故障定位方式。

对照 [验收步骤](references/acceptance.md) 检查自包含性。附上已验证和未验证事项，尤其是目标系统、模型变体和实际生成情况。
